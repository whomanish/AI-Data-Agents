# Bootstrap and capability building

Use this reference only for named setup, repair, inspection, a profile mismatch, or a failed quick check.

Derive the smallest capability set from the actual outcome. Cohorts start with usage signals. Email audiences add identity, user/customer context, eligibility and suppression, email activation, and measurement. In-app work adds the applicable identity, entitlement, exposure, frequency, activation, and measurement evidence without assuming email or CRM requirements.

Resolve the mutable overlay outside the installed skill, then inspect the runtime operations needed for that outcome. Check storage, persistence, deterministic execution, interpreter, network constraints, and each connector search, schema, query, export, or write operation separately. Connector presence does not prove an operation. Use harmless scratch probes only when appropriate; never probe a production write. If an operation is unavailable, state the system, minimum permission, test operation, and safe manual-file alternative.

Discover with least-sensitive evidence first: connector metadata, documentation, schema inspection, aggregate queries, and stratified minimal samples. Retrieve row-level data only when needed to resolve a material ambiguity, keep it in controlled files, and expose only aggregate or redacted status in conversation. Ask targeted questions only after safe discovery cannot determine a semantic or policy decision that changes the campaign.

Classify each gap: a safety blocker prevents the affected decision, an execution blocker narrows the supported outcome, and a deferrable enrichment is recorded without blocking unrelated work. Save non-PII evidence, scope, provenance, owner, blocker, and next verification operation in the affected overlay module. On resumption, validate existing work and perform only the missing step.

Build configuration-first adapters and deterministic helpers at the approved file boundary. Promote a capability to ready only with all required evidence; promote it to verified only after a controlled realistic run, output validation, and human confirmation. A successful verified family may compile a versioned profile with exact dependencies, quick checks, ranges, runner, and evidence. Do not place campaign rows, secrets, production results, or synthetic facts in the overlay. Session-only overlays require disclosed limits and a validated export for cross-session continuation.
